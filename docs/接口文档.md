# LarfnOS 前端 GUI ↔ 原生 C 层桥接接口文档

> 文档依据源码整理：`native/larfn-shell.c`、`native/bridge.c`、`native/bridge.h`、`gui/js/bridge.js`、`gui/js/sysapi.js`，辅助参考 `gui/js/app.js`、`gui/js/apps.js`、`gui/js/window-manager.js`、`gui/index.html`、`iso/build-iso.sh`、`README.md`。
> 源码版本：LarfnOS 1.0 (dev) / kernel 6.6.2-larfn（按项目内声明）。

---

## 1. 总体架构与消息通道

LarfnOS 采用「WebKitGTK 原生 GUI + 前端桌面 Shell」双层架构：

- **原生层（native/）**：`larfn-shell.c` 是 GTK/WebKitGTK 主程序，加载 `gui/index.html`（部署路径 `/usr/share/larfn/gui`），作为登录后的首层桌面界面；`bridge.c` 实现全部系统调用并以 `k_commands[]` 分发表路由。
- **前端层（gui/js/）**：`bridge.js` 负责建立 IPC 通道并封装 `MarvisBridge`；`sysapi.js` 在上层封装面向业务（桌面 Shell/内置应用）的系统 API `MarvisSys`。

### 1.1 通道名称与注册点

| 项目 | 内容 |
| --- | --- |
| ScriptMessageHandler 名称 | **`larfn`** |
| 注册位置（C） | `larfn-shell.c`：`webkit_user_content_manager_register_script_message_handler(ucm, "larfn")` |
| JS 发送接口 | `global.webkit.messageHandlers.larfn.postMessage(payload)` |
| C 接收信号 | `script-message-received::larfn` → `on_script_message()` |
| 前端可用的判定 | `!!(window.webkit && window.webkit.messageHandlers && window.webkit.messageHandlers.larfn)` → `HAS_NATIVE` |

### 1.2 请求消息格式（JS → Native）

```js
{ id: "req_<时间戳36进制><随机串>", cmd: "<命令名>", params: { ... } }
```

- `id`：调用方生成的唯一请求 ID，用于将异步回复与 Promise 对应（格式：`'req_' + Date.now().toString(36) + Math.random().toString(36).slice(2,8)`）。
- `cmd`：命令名，由原生层 `k_commands[]` 分发表匹配。
- `params`：命令入参对象（可选，缺省 `{}`）。

### 1.3 回复格式（Native → JS）

原生层通过 `larfn_reply()` 向页面注入 JS 调用：

```js
window.onNativeReply(req_id, ok, payloadJSON)
// 例：window.onNativeReply("req_lx2a...", true, "{\"cpu\":\"12.3\",...}")
```

- `req_id`：回显请求 ID。
- `ok`：`true` 成功 / `false` 失败。
- `payloadJSON`：JSON 字面量字符串；失败时通常含 `{"error":"..."}`。

前端 `bridge.js` 的 `window.onNativeReply` 依据 `__nativeResolvers[id]` 找到 Promise：成功 `resolve(data)`，失败 `reject(new Error(data.error || 'native error'))`。**超时**：8 秒未收到回复则删除 resolver 并 `reject(new Error('native timeout: ' + cmd))`。

### 1.4 事件推送（Native → JS，主动事件通道）

原生事件推送入口（`larfn-shell.c` 的 `native_push_event()`，通过 `bridge_set_event_sink()` 注册给 bridge 层）：

```js
window.onNativeEvent(typeJSON, dataJSON)
```

前端 `bridge.js` 的 `window.onNativeEvent` 收到后转发为 DOM 事件：

```js
global.dispatchEvent(new CustomEvent('native-event', { detail: { type, data } }));
```

**注意（如实标注）**：`bridge.h` 声明了 `EventSink`（type/json 均须为合法 JSON 字面量），`larfn-shell.c` 也在 `gtk_main()` 前注册了 `bridge_set_event_sink(native_push_event)`，注释注明"供 D-Bus 监听线程使用"；但当前 `bridge.c` 没有任何代码真正调用该 sink，即**原生→前端的事件推送链路已就绪但当前版本无事件源**。前端业务仍可通过 `sysapi.js` 的 `onEvent()` 订阅该通道，供未来原生事件（如通知、电量、网络状态变化）使用。

### 1.5 调用方向汇总

| 方向 | 通道 | 载体 |
| --- | --- | --- |
| 前端 → 原生（请求） | `messageHandlers.larfn` | `postMessage({id, cmd, params})` |
| 原生 → 前端（应答） | 页面 JS 注入 | `window.onNativeReply(id, ok, payload)` |
| 原生 → 前端（事件） | 页面 JS 注入 | `window.onNativeEvent(type, data)`（当前无事件源） |

## 2. native 层 `k_commands[]` 分发表（已实现命令）

`bridge.c` 中的命令表定义：

```c
static const CmdEntry k_commands[] = {
    { "sys.stats",    cmd_sys_stats },
    { "sys.listApps", cmd_sys_list_apps },
    { "app.launch",   cmd_app_launch },
    { "sys.exec",     cmd_sys_exec },
    { "sys.power",    cmd_sys_power },
    { "notify.send",  cmd_notify_send },
    { NULL, NULL }   // 结束哨兵
};
```

**未命中任何命令时**：`larfn_reply(view, req_id, FALSE, "{\"error\":\"unknown command\"}")`，即 ok=false。

> ⚠️ 重要事实核对：README 中声称的 `sys.listFiles`、`settings.*`、`system.info`、`wm.*` **并未在 native `k_commands[]` 中实现**，仅存在于前端调用方/降级 mock 中（详见第 4 节）。下表仅列出 C 层真正注册的 6 条命令。

### 2.1 sys.stats —— 系统实时状态

| 项目 | 内容 |
| --- | --- |
| 命令名 | `sys.stats` |
| 入参 params | 无（忽略 params） |
| 功能 | 读取 `/proc/stat`（两次采样 jiffies 差计算 CPU 占用）、`/proc/meminfo`（MemTotal/MemAvailable 计算内存占用）、`statvfs("/")`（磁盘占用）、`uname()`（内核信息）；net 字段探测 `/sys/class/net/` 是否存在 |
| 成功返回（ok=true） | `{"cpu":"12.3","mem":"41.0","disk":"37.6","net":"已连接","kernel":"Linux 6.6.2-larfn"}`（cpu/mem/disk 为百分比字符串，保留 1 位小数；首次采样 CPU 为 0） |
| 失败返回 | 一般不会失败；读取失败项按 0/未知兜底 |

**前端调用示例**：

```js
// sysapi.js: Sys.getStats()
MarvisSys.getStats().then(s => {
  console.log(s.cpu + '% CPU', s.mem + '% MEM', s.disk + '% DISK', s.kernel);
});
// app.js 顶栏每 3 秒轮询：document.getElementById('stat-cpu-mini').textContent = 'CPU ' + Math.round(+s.cpu) + '%';
```

### 2.2 sys.listApps —— 应用清单

| 项目 | 内容 |
| --- | --- |
| 命令名 | `sys.listApps` |
| 入参 params | 无（忽略 params） |
| 功能 | 扫描目录 `/usr/share/larfn/apps/*.json`，将每个 JSON 文件内容（应用描述对象）原样透传，拼成 JSON 数组返回；目录不存在/为空时返回 `[]` |
| 成功返回（ok=true） | `[{...应用描述...},{...}]`，形如 `[{"id":"terminal","name":"终端","svg":"...","exec":"kgx --new-window","kind":"native"}]` |
| 失败返回 | 目录不存在不报错，返回 `[]` |

**前端调用示例**：

```js
// sysapi.js: Sys.listApps()；app.js loadApps() 拉取后并入 Dock/启动台
MarvisSys.listApps().then(list => {
  list.forEach(a => { if (!window.Apps.lookup(a.id)) { /* 加入 AppRegistry */ } });
});
```

### 2.3 app.launch —— 拉起独立桌面应用

| 项目 | 内容 |
| --- | --- |
| 命令名 | `app.launch` |
| 入参 params | `appId`（必填，应用 ID 字符串） |
| 功能 | 构造 `/usr/share/larfn/apps/<appId>.desktop` 路径，用 `gio launch` 异步启动外部应用进程（stdout 丢弃） |
| 成功返回（ok=true） | `{"ok":true}` |
| 失败返回 | 缺 appId：`{"error":"missing appId"}`；启动失败：`{"error":"<gio 错误消息>"}` |

**前端调用示例**：

```js
// 直接走桥（MarvisBridge）
MarvisBridge.invoke('app.launch', { appId: 'terminal' }).then(r => console.log(r.ok));
// 业务层 sysapi.js 暂无此方法的专门封装（见 2.3 备注与第 6 节）
```

**备注（实现不一致，如实标注）**：`apps.js` 中 `Apps.external(id)` 调用的是 `MarvisSys.runCommand('app.launch ' + id)`（走 `sys.exec`），而 native `sys.exec` 白名单前缀并不含 `app.launch`，因此该外部应用拉起通道在当前原生实现下会被白名单拒绝；与 `k_commands[]` 中独立的 `app.launch` 命令不是同一条链路。如需拉起外部应用，应使用本节 `MarvisBridge.invoke('app.launch', {appId})` 通道（在原生层补齐 desktop 文件与命令注册后可工作）。

### 2.4 sys.exec —— 受限命令执行

| 项目 | 内容 |
| --- | --- |
| 命令名 | `sys.exec` |
| 入参 params | `cmd`（必填，命令字符串） |
| 功能 | 通过 `/bin/sh`（`g_spawn_command_line_sync`）同步执行命令，**仅允许以下前缀白名单**：`ls `、`pwd`、`df `、`free `、`uname `、`uptime`、`cat /etc/os-release`、`systemctl --user ` |
| 成功返回（ok=true） | `{"stdout":"<命令输出，JSON 转义>"}`（空输出为 `{"stdout":""}`） |
| 失败返回 | 缺 cmd：`{"error":"missing cmd"}`；不在白名单：`{"error":"command not in allowlist"}`；执行失败：`{"error":"<错误消息>"}` |

**前端调用示例**：

```js
// sysapi.js: Sys.runCommand(cmd)；apps.js 终端 App 每敲一行命令调用一次
MarvisSys.runCommand('uname -a').then(r => console.log(r.stdout));
MarvisSys.runCommand('rm -rf /').catch(e => console.error(e.message)); // 白名单拒绝
```

### 2.5 sys.power —— 电源操作

| 项目 | 内容 |
| --- | --- |
| 命令名 | `sys.power` |
| 入参 params | `action`（必填，枚举：`shutdown` / `reboot` / `suspend` / `logout`） |
| 功能 | 映射目标并异步执行 `busctl call org.freedesktop.login1 /org/freedesktop/login1 org.freedesktop.login1.Manager <target> s false`（target 映射：shutdown→poweroff、reboot→reboot、suspend→suspend、logout→logout），由 systemd-logind 经 polkit 授权后执行（授权弹窗由系统层负责）；异步返回，不等系统真正关机/重启 |
| 成功返回（ok=true） | `{"ok":true}` |
| 失败返回 | 缺 action：`{"error":"missing action"}`；未知 action：`{"error":"unknown action"}`；spawn 失败：`{"error":"<错误消息>"}` |

**前端调用示例**：

```js
// sysapi.js: Sys.power(action)；app.js 电源对话框 / 设置页按钮
MarvisSys.power('shutdown').then(() => toast('正在关机…'));
MarvisSys.power('reboot').then(() => toast('正在重启…'));
MarvisSys.power('suspend'); MarvisSys.power('logout');
```

### 2.6 notify.send —— 桌面通知

| 项目 | 内容 |
| --- | --- |
| 命令名 | `notify.send` |
| 入参 params | `title`（可选，缺省 `"LarfnOS"`）、`body`（可选，缺省 `""`） |
| 功能 | 异步执行 `gdbus call --session --dest org.freedesktop.Notifications --object-path /org/freedesktop/Notifications --method org.freedesktop.Notifications.Notify "larfn-shell" 0 "" <title> <body> "[]" "{}" 5000`，发送真实系统通知（app="larfn-shell"，replaces_id=0，无图标，超时 5000ms） |
| 成功返回（ok=true） | `{"ok":true}`（无论通知是否真正弹出，spawn 成功即 ok） |
| 失败返回 | spawn 失败：`{"error":"<错误消息>"}` |

**前端调用示例**：

```js
// sysapi.js: Sys.notify(title, body)
MarvisSys.notify('欢迎使用 LarfnOS', '图形外壳已就绪，点击下方 Dock 图标打开应用。');
// app.js bootNotice() 启动引导通知；apps.js 文件管理器选中文件时通知文件名
```

## 3. native 层其他结构（未形成分发表条目的接口）

### 3.1 bridge.h 公开函数

| 函数 | 签名 | 用途 |
| --- | --- | --- |
| `bridge_set_event_sink` | `void (EventSink sink)` | 注册原生事件推送回调（type/json 均为 JSON 字面量） |

### 3.2 params 读取辅助（bridge.c 内部）

- `jsc_param_bool(params, key, def)`：读布尔参数，缺省返回 def。
- `jsc_param_str(params, key)`：读字符串参数，缺省返回 NULL。
- `json_escape(s)`：JSON 字符串转义（`"`、`\`、`\n`、`\r`、`\t`、<0x20 转 `\uXXXX`）。

## 4. 前端已声明但 native 分发表未实现的命令（预留扩展点 / Mock 专用）

以下命令**在 native `k_commands[]` 中不存在**：原生环境调用会得到 `ok=false + {"error":"unknown command"}`。它们仅存在于 `sysapi.js`（作为调用方）与 `bridge.js` mock 降级层（提供演示数据）。归类为「前端预留扩展点」。

### 4.1 sys.listFiles —— 文件列表（native 未实现）

| 项目 | 内容 |
| --- | --- |
| 命令名 | `sys.listFiles` |
| 入参 params | `path`（可选，mock 支持 `home` / `docs` / `pics` / `down`，缺省 `home`） |
| mock 返回 | `{"path":"/home","items":[{"n":"文档","d":true},{"n":"readme.txt","d":false},...]}`（`d=true` 为目录） |

**前端调用示例**：

```js
// sysapi.js: Sys.listFiles(path)
MarvisSys.listFiles('home').then(r => {
  console.log(r.path);           // "/home"
  (r.items || []).forEach(it => console.log(it.n, it.d ? '[目录]' : '[文件]'));
});
```

> 原生层若需落地：建议在 `k_commands[]` 增加 `sys.listFiles`，扫描目录并输出同构 JSON（`{path, items:[{n,d}]}`）。文件管理器状态栏会根据 `MarvisBridge.hasNative` 显示"原生 sys.listFiles / 演示数据源"。

## 5. bridge.js —— IPC 通道与 API 清单

### 5.1 全局对象/函数

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `MarvisBridge.invoke(cmd, params)` | Function → Promise | 统一 IPC 入口：组装 `{id, cmd, params}`，原生存在时 `postMessage` 到 `messageHandlers.larfn` 并注册 8s 超时；否则走 `mockInvoke` |
| `MarvisBridge.hasNative` | Boolean | 是否存在 `window.webkit.messageHandlers.larfn`（原生通道判定） |
| `window.onNativeReply(id, ok, data)` | Function | 原生应答注入点：按 id 匹配 resolver，resolve/reject Promise |
| `window.onNativeEvent(type, data)` | Function | 原生事件注入点：转成 `CustomEvent('native-event', {detail:{type,data}})` 派发到 window |
| `__nativeResolvers` | Object（动态） | 未完成请求的 Promise 注册表（`id -> {resolve,reject}`） |

### 5.2 mock 降级行为（无原生环境）

判定：浏览器中无 `window.webkit.messageHandlers.larfn`（如直接用浏览器打开 `gui/index.html` 调试）时 `HAS_NATIVE=false`，所有 `invoke` 走 `mockInvoke(cmd, params)`：先延迟 `90 + random*150` ms 模拟异步，再按命令返回演示数据。

| 命令 | mock 行为 |
| --- | --- |
| `sys.stats` | cpu/mem 在区间内随机浮动（CPU 2-95、MEM 12-90），固定返回 disk=37.6、net=`以太网 已连接`、kernel=`6.6.2-larfn (debug-mode)`、ip=`192.168.1.108` |
| `sys.listApps` | 返回 5 个内置应用：files/editor/terminal/settings/about（name/kind/icon/color） |
| `sys.listFiles` | 按 params.path 返回 MOCK_FILES 中 home/docs/pics/down 的条目；未知路径返回空 items |
| `sys.exec` | 见下方 `execMock` 表格 |
| `sys.power` | `{"ok":true,"action":params.action}`（不执行真实电源操作） |

## 7. 前端事件消息与窗口系统（window-manager.js / app.js）

### 7.1 window-manager.js 对外 API

| 名称 | 签名 | 说明 |
| --- | --- | --- |
| `WindowManager.createWindow(app, opts)` | `(app, {width,height,x,y,title}) => rec` | 创建窗口；返回窗口记录 rec（含 el/body/titlebar、focus/minimize/toggleMax/close/setContent 方法、minimized/maximized 状态） |
| `WindowManager.windowsOf(appId)` | `(appId) => [rec,...]` | 某应用已打开的窗口列表 |
| `WindowManager.allWindows()` | `() => [rec,...]` | 所有窗口 |
| `WindowManager.focusedWindow()` | `() => rec \| null` | 当前聚焦窗口 |

### 7.2 窗口事件消息

window-manager.js 内部在**窗口创建、关闭、聚焦变化（setFocus）、最小化**时派发 DOM 事件（非原生 IPC）：

```js
document.dispatchEvent(new CustomEvent('dock:update'));
```

- 事件名：`dock:update`（挂在 `document` 上，无 detail）。
- 消费者：`app.js` 中 `document.addEventListener('dock:update', syncDock)` —— 重扫 Dock 图标，切换 `running`/`focused` 类显示"运行中/聚焦"圆点。
- 消息方向：纯前端窗口状态 → Dock 同步，**不经原生桥**。

### 7.3 桌面应用启动链路（app.js）

1. `loadApps()`：先注入内置应用（`Apps.builtins`），再 `Sys.listApps()` 拉原生清单补充不在内置注册表中的应用（kind 缺省 external，用 genericIcon），随后 `renderLauncher()` + `renderDock()`。
2. `App.launch(id)`：`Apps.lookup(id)` 找到应用；已有窗口则聚焦，否则 `WindowManager.createWindow` + `app.launch(rec.body)`；未找到时 `Sys.notify('LarfnOS', '未找到应用：'+id)`。
3. Dock 图标点击：运行中窗口 → 焦点切换/最小化；未运行 → `App.launch(a.id)`。

## 8. 通知与开机自启相关

### 8.1 通知链路

- **命令通道**：前端 `Sys.notify(title, body)` → `notify.send` → native `gdbus` 调 `org.freedesktop.Notifications.Notify`（详见 §2.6）。
- **前端通知使用点**：
  - `app.js bootNotice()`：启动后延时 900ms 发欢迎通知（先 `Sys.getInfo()` 取系统名，缺失回落 LarfnOS）。
  - `apps.js` 文件管理器：点击文件项时 `notify(文件名, '已选择文件')`。
  - `apps.js` 编辑器：Ctrl+S（Cmd+S）保存时 `notify('编辑器', '已保存（演示会话）')`。
- **UI 元素**：`index.html` 有 `#toast-root` 与 `#notification-stack` 两个容器；toast 由 `app.js` 的 `LarfnToast(msg)` 实现；系统通知原生返回后**不会**注入前端 notification-stack（当前版本系统通知只出现在桌面通知中心，前端事件通道无对应事件源，见 §1.4）。
- **原生事件预留**：`native_push_event`（larfn-shell.c）已实现并注册，桥头注释称供 D-Bus 监听线程使用；如未来由原生监听 `org.freedesktop.Notifications` 或 logind 信号，可通过该 sink 推送 `{type:'notify', ...}` / 电源事件到 `MarvisSys.onEvent` 订阅者。

### 8.2 开机自启

开机自启**不通过 IPC 消息**实现，均由 systemd 单元/部署脚本完成：

| 文件 | 机制 | 内容 |
| --- | --- | --- |
| `iso/usr_lib_systemd_user/larfn-shell.service` | 用户图形会话自启（make install 安装到 `/usr/lib/systemd/user/`） | `After=graphical-session.target`、`ExecStart=/usr/bin/larfn-shell`、`Restart=on-failure`、`RestartSec=2`、`Environment=GDK_BACKEND=wayland,x11`、`WantedBy=graphical-session.target` |
| `iso/build-iso.sh` 生成的 `larfn-autostart.service` | system 级 graphical.target 依赖（chroot 内写入） | `After=graphical.target`、`ConditionUser=!root`、`ExecStart=/usr/bin/larfn-shell`、`Restart=on-failure`，软链到 `graphical.target.wants/`；同时 `systemctl disable sddm` 避免桌面冲突 |
| `iso/build-iso.sh` 生成的 `/etc/skel/.profile` | 登录 tty 兜底 | 无 DISPLAY/WAYLAND_DISPLAY 时 `exec /usr/bin/larfn-shell` |
| `org.larfn.shell.desktop`（build-iso.sh 写入 `/usr/share/applications`） | Desktop Entry | `Exec=/usr/bin/larfn-shell`、`NoDisplay=true`、`X-GNOME-Autostart-enabled=true` |

部署路径汇总：二进制 `/usr/bin/larfn-shell`，GUI 前端 `/usr/share/larfn/gui/`，应用清单 `/usr/share/larfn/apps/*.json`（样例 terminal.json：`{"id":"terminal","name":"终端","svg":"...","exec":"kgx --new-window","kind":"native"}`）。
